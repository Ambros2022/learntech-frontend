# HTML → Next.js Landing Page Conversion Playbook

How to turn a standalone design handoff (`index.html` + `style.css` + `script.js` + asset folders) into a server-rendered landing page in this repo that **looks and behaves exactly like the handoff**, ranks, and keeps Core Web Vitals green.

Reference implementation: `src/app/(landing)/online-degree-courses-in-india/` (verified pixel-identical to its handoff at 390/768/1440px).

Placeholders used below:

| Placeholder | Example | Meaning |
| :--- | :--- | :--- |
| `<slug>` | `online-degree-courses-in-india` | URL segment / route folder |
| `<assets>` | `online-degree` | folder under `public/images/` |
| `<Name>` | `OnlineDegree` | PascalCase file prefix |
| `<name>Root` | `onlineDegreeRoot` | wrapper class in the CSS module |

## 1. Architecture

Landing pages live in `src/app/(landing)/<slug>/`. The group layout `src/app/(landing)/layout.tsx` is a pass-through, so landing pages never get the site header/footer. They still get the **root layout**: Bootstrap CSS, `styles/globals.css`, `ClientProviders` (NProgress, Bootstrap JS). §5.3 lists what leaks in from those.

### File layout

```text
src/app/(landing)/<slug>/
 ├── page.tsx                         [server] metadata, canonical, JSON-LD
 ├── <Name>Content.tsx                [server] ALL markup, in handoff order: navbar, sections, footer,
 │                                             back-to-top, interactive widgets' markup (cards, dropdowns,
 │                                             results, FAQ answers) — then <Name>BehaviorsClient />
 ├── <Name>EnquiryTriggerClient.tsx   [client] page root wrapper (stands in for <body>): CSS-module root
 │                                             class + font variables, one delegated click → popup
 ├── <Name>BehaviorsClient.tsx        [client] renders null; ports script.js onto the server DOM
 ├── <Name>EnquiryModalClient.tsx     [client] popup form → Learntech API
 ├── <Name>Data.ts / <Name>FaqData.ts [data]   arrays shared by markup + JSON-LD
 ├── <Name>Fonts.ts                   [opt]    page-only next/font weights the site font lacks
 └── <Name>.module.css                [styles] generated by scripts/scope-landing-css.cjs
```

```tsx
// page.tsx
<OnlineDegreeEnquiryTriggerClient>   {/* <div className={`${styles.root} ${poppins.variable}`} onClick=…> */}
  <OnlineDegreeContent />            {/* server: <header>, <main>…</main>, <footer>, <BehaviorsClient/> */}
</OnlineDegreeEnquiryTriggerClient>
```

### Rules that make it work

1. **Everything renders inside the root wrapper.** Every scoped selector starts with the root class. Anything rendered outside it (a navbar, a "client island" section) gets **no styles at all**.
2. **Markup is server HTML, in handoff order.** Do not move sections into client components. If the handoff builds markup in JS (`rail.innerHTML = …`, result lists), render the full set on the server and let JS show or hide it. Crawlable, and no layout jump.
3. **Behaviour is one imperative island.** Port `script.js` almost line-for-line into a `useEffect` in `<Name>BehaviorsClient`. Do not rewrite the design's widgets as React state: the handoff CSS depends on the exact classes and inline styles its JS toggles (`.in`, `.vis`, `.is-open`, `--mx`, `transform`, …).
4. **The parent never re-renders the content.** `TriggerClient` re-renders when the popup opens, but `children` is the same element reference, so React leaves the server DOM (and the classes JS added) alone.

## 2. SEO & Core Web Vitals

- Exactly one `<h1>` (hero). `<h2>` per section, `<h3>` for cards and steps.
- All ranking content and internal links in server HTML; hidden states use `hidden`/CSS, not conditional rendering.
- Hero text and logo in SSR HTML; logo `<img … fetchPriority="high">` (vector logo — `next/image` adds nothing and warns when CSS sizes it per breakpoint).
- Explicit `width`/`height` on images; `loading="lazy"` below the fold.
- Reveal-on-scroll content starts at `opacity: 0`. Add a no-JS fallback at the end of Content:
  ```tsx
  <noscript><style>{'.rv,.aic-card,.pc,.hw-card{opacity:1!important;transform:none!important}'}</style></noscript>
  ```
- Animation loops: `requestAnimationFrame`, paused with `IntersectionObserver` when off-screen; passive scroll listeners.
- JSON-LD via `src/app/components/JsonLd.tsx`: `WebPage`, `EducationalOrganization`, `ItemList`/`Course`, `FAQPage` (built from `<Name>FaqData.ts`, the same array the FAQ markup uses).

## 3. Lead form API

```env
NEXT_PUBLIC_WEB_URL=https://learntechww.com
NEXT_PUBLIC_API_URI=https://newapi.learntechww.com/
```

`POST ${NEXT_PUBLIC_API_URI}/api/website/landingpage/enquiry` — `multipart/form-data`:

| Key | Example |
| :--- | :--- |
| `name` | `Rahul Sharma` |
| `email` | `rahul@example.com` |
| `contact_number` | `+91-9876543210` |
| `location` | `Karnataka` |
| `course_in_mind` | `Online MBA` |
| `description` | `Enquiry for Online MBA from state Karnataka` |
| `current_url` | `window.location.href` |
| `Source` | `Google Ads` |
| `SourceCampaign` | page campaign name |

```tsx
const API_URI = (process.env.NEXT_PUBLIC_API_URI || 'https://newapi.learntechww.com/').replace(/\/+$/, '')

const fd = new FormData()
fd.append('name', form.name.trim())
fd.append('email', form.email.trim())
fd.append('contact_number', `+91-${form.phone.replace(/\D/g, '')}`)
fd.append('location', form.state)
fd.append('course_in_mind', form.course)
fd.append('description', `Enquiry for ${form.course} from state ${form.state}`)
fd.append('current_url', window.location.href)
fd.append('Source', 'Google Ads')
fd.append('SourceCampaign', '<CAMPAIGN_NAME>')
const res = await fetch(`${API_URI}/api/website/landingpage/enquiry`, { method: 'POST', body: fd })
// res.ok → toast.success(…) + router.push('/thank-you'); else toast.error(…)
```

Popup rules:
- Keep it **always mounted** and toggle the design's open class (e.g. `popup-overlay active`) so its CSS transition runs. A `visibility: hidden` closed state keeps it out of the tab order.
- Close on ×, overlay click, `Esc`; focus the first field on open; lock body scroll.
- Pre-select the course the visitor clicked: put `data-course-name="<exact option value>"` on cards. Resolve free text (finder results) against the option list with exact match → `"X (Y)"` → `"X in Y"` → first option sharing the first two words.

## 4. Conversion procedure

1. **Assets** — copy handoff folders to `public/images/<assets>/` (same sub-structure).
2. **CSS** — generate the module (§5). Read the warnings.
3. **Data** — move repeated content (cards, partners, FAQ, steps, testimonials, JS data arrays) into `<Name>Data.ts`.
4. **Markup** — port `index.html` to `<Name>Content.tsx` section by section, same order, same classes and ids (§6). Include markup the handoff JS generates.
5. **Behaviour** — port `script.js` to `<Name>BehaviorsClient.tsx` (§7). Skip sections whose elements don't exist in the HTML (dead demo code is common).
6. **Popup** — `<Name>EnquiryModalClient.tsx` using the handoff popup markup + §3.
7. **Root + page** — `TriggerClient` wrapper, `page.tsx` metadata and JSON-LD.
8. **Verify** — §9, against the live handoff, at 390 / 768 / 1024 / 1440px.

## 5. CSS

### 5.1 Generate

```bash
node scripts/scope-landing-css.cjs <handoff>/style.css \
  "src/app/(landing)/<slug>/<Name>.module.css" \
  --root=<name>Root --slug=<assets> --html=<handoff>/index.html \
  --important='nv-link:color'            # one per globals.css !important leak (see 5.3)
```

What the generator does, and why:

| Transform | Why |
| :--- | :--- |
| `:root` / `html` / `body` → `.<name>Root` | the wrapper div stands in for the document |
| `html.x` / `body.x` → `:global(html.x)` | state classes the JS toggles on the document (`nv-lock`, `enq-open`) |
| everything else → `:where(.<name>Root) :global(sel)` | `:where()` adds **zero specificity**, so the design cascades against Bootstrap exactly as in the handoff. A plain `.root *` prefix would make `* { margin: 0 }` beat Bootstrap's `h1/p/ul` margins and change all spacing. |
| pseudo-elements kept outside `:global()` | required by CSS Modules |
| recurses `@media`, `@supports`, `@container`, `@layer` | rules inside unscoped at-rules get hashed into dead local classes |
| relative `url(media/x.jpg)` → `/images/<assets>/media/x.jpg` | assets moved to `public/` (data:, absolute and `/` URLs untouched) |
| `font-size` → `!important` | globals.css forces `p { font-size: 16px !important }`; generator also prepends a `p { font-size: inherit !important }` reset |
| `"Poppins"` → `var(--font-poppins), "Poppins"` | next/font can register a hashed family name |
| `--html` without `<main>` → drops rules targeting `main` | the page wraps sections in `<main>`; rules like `main>section { min-height: 90vh }` were dead in the handoff and would suddenly apply |
| appends host-isolation block | §5.3 |

### 5.2 After generating

- **Class names you add must not exist in `style.css`.** Handoff CSS often has unused classes (`.course-finder__intro` existed but wasn't in the HTML — reusing the name pulled in its margins). `grep -c "<class>" <handoff>/style.css` before naming.
- Inline styles from the HTML that use `!important` can't be expressed in React — move them to a class in the module.
- `<html>`-level properties (`scroll-padding-top`, `scroll-behavior`) don't work on a div. The generator converts the nav offset to `scroll-margin-top` on `section[id]`; set `--landing-nav-offset` on the root if the navbar height differs from 84px.
- Page-specific additions go **after** the generated content, with a comment, so regeneration is a clean diff.

### 5.3 Host-app leaks (root layout CSS)

These come from `styles/globals.css` and apply to every landing page:

| Leak | Effect | Fix |
| :--- | :--- | :--- |
| `p { font-size: 16px !important }` | every paragraph 16px | generator (font-size `!important` + `p` reset) |
| `@media (max-width:767px) { header { display:none !important } }` | navbar (and any `<header>`) vanishes on mobile | isolation block: `.root :global(header) { display: block !important }` |
| `nav a { color: black !important }` | nav link colors / active state lost | `--important='<nav-link-class>:color'` |
| `select { background: transparent !important; color: white !important }`, `select:focus { border-color: white !important }` | invisible text in popup dropdowns | default `--important='\bselect\b:color,background,background-color,border-color'` |
| `a { text-decoration: none !important }` | only matters if the design underlines links | `--important='<selector>:text-decoration'` |
| wrapper `overflow-x: hidden` (from `body`) | turns the wrapper into a scroll container → `position: sticky` stops working | isolation block uses `overflow-x: clip` |

Also from the root layout:
- `NProgressBar` scrolls to top on mount unless the URL has a `#hash` (fixed in `src/app/components/NProgressBar.tsx`).
- Fonts: the site Poppins (`src/fonts.ts`) loads weights 300–700. If the design uses 800/900, add `<Name>Fonts.ts` with `preload: false` and point only those rules at its variable (`font-family: var(--font-poppins-heavy), var(--font)`).

## 6. Markup porting rules

- **JSX drops whitespace across line breaks.** HTML `Learn\n<span>…</span>` renders a space; JSX doesn't. Check every inline run that spans lines (headlines with inline icons, sentences with inline dropdowns) and add `{' '}`. The text-compare in §9 catches these.
- Keep every class, id, `data-*` and `aria-*` the CSS/JS uses. Keep CSS custom properties from inline styles: `style={{ '--i': idx } as React.CSSProperties}`.
- JS-generated markup → server-rendered:
  - card rails/sliders → render **all** cards; filters set `style.display = 'none'`. Don't use the `hidden` attribute: author `display` rules override it.
  - one-of-N results → render all, `hidden` on all but the default (if the design CSS doesn't set `display` on them).
  - marquee clones (logo walls) → render the second copy on the server with `aria-hidden` and `alt=""`.
  - wrappers/arrow buttons the JS injects (e.g. `.chw` + `.chn`) → render them on the server, `hidden` initially.
- Navbar links → real `href="#section-id"` (crawlable, works without JS). §7.2 removes the URL side effect.
- Enquiry CTAs → `href="#cta"` / `data-enq` / `.open-enquiry-popup`; `TriggerClient` intercepts them.
- External demo images in the handoff (e.g. `i.pravatar.cc` avatars) — keep for parity, flag to the user for real assets.

## 7. Behaviour island

### 7.1 Template

```tsx
'use client'
import { useEffect } from 'react'

export default function <Name>BehaviorsClient() {
  useEffect(() => {
    const ac = new AbortController()
    const signal = ac.signal                       // pass { signal } to every addEventListener
    const timers: number[] = [], intervals: number[] = []
    const observers: (IntersectionObserver | ResizeObserver)[] = []
    const rafs = new Set<number>()
    let disposed = false
    const $ = <T extends Element = HTMLElement>(s: string, r: ParentNode = document) => r.querySelector<T>(s)
    const $$ = <T extends Element = HTMLElement>(s: string, r: ParentNode = document) => Array.from(r.querySelectorAll<T>(s))
    const raf = (fn: FrameRequestCallback) => { const id = requestAnimationFrame((t) => { rafs.delete(id); if (!disposed) fn(t) }); rafs.add(id); return id }
    const later = (fn: () => void, ms: number) => { timers.push(window.setTimeout(fn, ms)) }
    const every = (fn: () => void, ms: number) => { intervals.push(window.setInterval(fn, ms)) }
    const io = (cb: IntersectionObserverCallback, o?: IntersectionObserverInit) => { const x = new IntersectionObserver(cb, o); observers.push(x); return x }
    const reduce = window.matchMedia('(prefers-reduced-motion: reduce)').matches

    /* ---------- one block per script.js section, same order ---------- */

    return () => {
      disposed = true
      ac.abort()
      timers.forEach(clearTimeout); intervals.forEach(clearInterval)
      observers.forEach((o) => o.disconnect()); rafs.forEach(cancelAnimationFrame)
      document.documentElement.classList.remove('nv-lock')   // any document-level class the JS sets
    }
  }, [])
  return null
}
```

Rules:
- Port logic as-is: same thresholds, easing, class names, CSS variables. Use the helpers so nothing leaks.
- The effect runs twice in dev (Strict Mode), so make it idempotent. Before re-cloning, remove the clones the first run left (`$$('[data-c]').forEach(e => e.remove())`). Select originals with `:not([data-c])`. Don't wrap or move server nodes; render wrappers on the server (§6).
- Set the state classes the handoff sets at init (`is-armed`, initial `--i` on nav links …), or render them on the server.
- Fix obvious handoff bugs only when they hurt users (e.g. scroll-spy `data-spy` values pointing at the wrong sections), and mention it.

### 7.2 In-page navigation without `#hash` in the URL

Links keep `href="#id"`. One delegated listener scrolls instead of navigating. The offset under the fixed navbar comes from `scroll-margin-top` (§5.2), so no magic numbers:

```ts
const scrollToId = (id: string) => {
  const behavior: ScrollBehavior = reduce ? 'auto' : 'smooth'
  if (id === 'top') { window.scrollTo({ top: 0, behavior }); return true }
  const el = document.getElementById(id)
  if (!el) return false
  el.scrollIntoView({ behavior, block: 'start' })
  return true
}

document.addEventListener('click', (e) => {
  if (e.defaultPrevented || e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey) return
  const a = (e.target as Element).closest?.<HTMLAnchorElement>('a[href^="#"]')
  if (!a) return
  const id = decodeURIComponent(a.getAttribute('href')!.slice(1))
  if (id && scrollToId(id)) e.preventDefault()          // #cta etc. have no target → popup handler owns them
}, { signal })

// Arrived via /<slug>#section: scroll after hydration settles, THEN strip the hash.
// (Parent effects such as NProgressBar run after this child effect and still need to see the hash.)
const initial = decodeURIComponent(window.location.hash.slice(1))
if (initial) {
  const go = () => later(() => {
    scrollToId(initial)
    window.history.replaceState(window.history.state, '', window.location.pathname + window.location.search)
  }, 100)
  if (document.readyState === 'complete') go()
  else window.addEventListener('load', go, { once: true, signal })
}
```

The navbar's own click handler (close mobile menu, set active link) still runs, because it is registered on the link itself.

### 7.3 Mobile navigation drawer & active link tracking (Scroll-Spy)

Mobile navigation must visually and functionally match the design on all viewport heights (down to 485px):

1. **Positioning & Solid Background**:
   - The mobile menu drawer `.nav` must be anchored directly under the header with `position: fixed !important; top: var(--nav, 64px) !important; left: 0 !important; right: 0 !important; width: 100% !important; z-index: 99 !important;`.
   - **Solid background is mandatory**: Always use `background: #ffffff !important;` (not transparent or low-opacity `rgba`), so hero headline text does not bleed through.
   - Max height & smooth slide:
     ```css
     .nav {
       max-height: 0 !important;
       overflow: hidden !important;
       visibility: hidden !important;
       transition: max-height .35s var(--ease), visibility 0s .35s;
     }
     .nav.open {
       max-height: calc(100dvh - var(--nav, 64px)) !important;
       overflow-y: auto !important;
       -webkit-overflow-scrolling: touch !important;
       visibility: visible !important;
       transition: max-height .35s var(--ease);
     }
     ```
2. **Full-width dividers & item layout**:
   - The list `.nav__links`, each `li`, and each `a:not(.btn)` must be `display: block !important; width: 100% !important; box-sizing: border-box !important;`.
   - Under each link, add full horizontal divider lines: `border-bottom: 1px solid var(--line, #E6EAF3) !important;`. Set `border-bottom: none !important;` on the last item.
3. **Viewport height budgeting**:
   - On small screens (e.g. 425x485px), total available height below a 64px navbar is ~421px. Budget item padding (e.g. `padding: 12px 0 !important;` and `.nav__links` padding `4px var(--gutter) 20px !important;`) so that all items (7+ links) fit on screen simultaneously without the last item (`FAQs`) being pushed below the fold.
4. **Body scroll lock**:
   - On open: `document.body.style.overflow = 'hidden'`.
   - On close & unmount cleanup: `document.body.style.overflow = ''`.
5. **Scroll-Spy & active link highlighting**:
   - Observe `section[id], main[id]` with an `IntersectionObserver` (`rootMargin: '-30% 0px -60% 0px'`).
   - When intersecting, toggle `.is-active` and `.active` on the corresponding `#mainNav .nav__links a` element.
   - Lock spy observer during programmatic in-page smooth scrolls (`lockSpyUntil = Date.now() + 800`) so intermediate sections don't flicker active while scrolling.
6. **Watch out for duplicate media queries from older drafts**:
   - Design handoffs often contain an older `@media (max-width: 767px)` block (e.g. an early horizontally-scrolling nav bar with `.header__inner { flex-wrap: wrap; height: auto; }` and `.nav { order: 3; }`) before the hamburger drawer was added. Always remove the obsolete block so it doesn't break header height or drawer placement.

### 7.4 Popup delegation (`TriggerClient`)

## 8. Images & fonts

- **Every image must have a descriptive `alt` attribute**:
  - Always provide meaningful `alt` text on `<img>` tags (e.g. `alt="Dubai skyline"`, `alt="Easy Accessibility icon"`, `alt="Symbiosis International University Dubai campus"`, `alt="Aarav - Working Professional"`).
  - **Never leave `alt` empty (`alt=""`) or omit it** on content, feature icons, logos, campus cards, avatars, or banner graphics. Good alt attributes are essential for SEO indexing, image search, and accessibility compliance.
  - Assets live under `/images/<assets>/…`.
- Plain `<img>` with `width`/`height` is fine where the handoff CSS sizes the image (logos, card thumbnails); add `// eslint-disable-next-line @next/next/no-img-element`. Use `next/image` for large raster photos that benefit from resizing.
- Fonts: §5.3. Never add a Google Fonts `<link>`.

## 9. Verification (against the live handoff)

Run every step and report actual results.

1. `npx tsc --noEmit -p tsconfig.json` and `npx eslint "src/app/(landing)/<slug>"` must be clean.
2. **Structure** (Playwright or DevTools, both pages, 390/768/1440px): document height and each section's top/height must match. Large mismatches mean a section is outside the root, out of order, or a rule is leaking.
3. **Text**: compare each section's `textContent` with all whitespace stripped. Then compare with whitespace collapsed, which catches JSX-dropped spaces (only differences inside inline runs matter).
4. **Metrics**: for every element in each section compare width, height, `font-size`, `line-height`, `font-weight`. The first divergence points at the rule. Typical causes are a class collision, a globals.css leak, an unscoped at-rule, or a missing font weight.
5. **Pixels**: viewport screenshots at each section top with animations paused (`*{animation-play-state:paused!important;transition:none!important}`), diffed with pixelmatch. Expect ≈0% except canvases and marquees. Use `behavior: 'instant'` when scrolling for captures.
6. **Behaviour**, desktop + mobile:
   - nav links scroll to the right section, the URL stays clean, the active link updates;
   - mobile menu opens/closes with scroll lock;
   - mobile menu has solid white background `#fff`, full-width dividers, and all nav items fit within 485px screen height;
   - `/<slug>#section` deep link scrolls there and the hash is removed;
   - sliders, filters, dropdowns (mouse + keyboard), accordion, back-to-top, marquee drag;
   - popup opens from every CTA, the right course is pre-selected, and it closes via ×, overlay and `Esc`.
7. **Form**: mock the API in the browser test (`page.route('**/landingpage/enquiry', …)` → 200) so no junk leads reach production. Check validation, the payload fields, the toast and the `/thank-you` redirect.
8. **No horizontal scroll** at 375/768/1024/1440; no console errors or hydration warnings.
9. **JavaScript disabled**: one h1; all cards, FAQ answers and nav links present and visible; canonical + JSON-LD in `<head>`.

## 10. Pitfalls seen in practice

| Symptom | Cause |
| :--- | :--- |
| Navbar unstyled / 1900px tall, sections after the footer | component rendered outside the root wrapper |
| Spacing slightly off everywhere | scoped `*`/element rules out-specifying Bootstrap — use the generator (`:where`) |
| Every section 90vh tall | handoff `main>section` rules activated by our `<main>` — `--html` drops them |
| Logos/rows wrong only on small cards | rules inside `@container` not scoped |
| Words run together in a headline | JSX whitespace (§6) |
| Paragraph margin/line-height differs | your new class name already existed in `style.css` |
| Navbar missing on phones | globals.css `header { display: none !important }` |
| Mobile drawer hero text bleeding through | drawer has semi-transparent background — use `background: #ffffff !important` |
| Mobile drawer dividers missing or partial width | drawer links missing `display: block !important; width: 100% !important; border-bottom: 1px solid var(--line) !important` |
| Mobile drawer links cut off / FAQs hidden | excessive vertical padding pushing items below 485px viewport — budget padding (`12px 0`) |
| Header height blown out / nav misaligned on mobile | obsolete `@media (max-width: 767px)` block from earlier draft handoffs overriding `.header__inner` |
| Popup dropdown text invisible | globals.css `select { color: white !important }` |
| Sticky stack doesn't stick | wrapper `overflow-x: hidden` — use `clip` |
| Anchor jumps hide the heading under the navbar | `scroll-padding-top` on html — use `scroll-margin-top` |
| URL gains `#section` on every click | missing §7.2 interception |
| Deep link `#section` lands at top | NProgressBar scroll-to-top, or hash stripped before parent effects ran |
| Popup asset 404 | `url()` rewritten twice — generator rewrites relative URLs only |
| Images missing alt / empty `alt=""` | must always provide descriptive alt text for accessibility and SEO |
